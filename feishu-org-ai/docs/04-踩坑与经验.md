# 四、踩坑与经验

## 1. 后端首次启动直接 500：忘了迁移

现象：服务能起来，任何接口都报错。

原因：数据库文件为空，表不存在。

处理：先跑 `python scripts/dev.py migrate`，再启动 API。项目把迁移封装在统一入口里，直接调 alembic 会因配置路径不对报错。

## 2. 页面白屏：React Hooks 顺序被打乱

现象：改完页面后整页白屏，控制台提示 hook 数量在两次渲染间不一致。

原因：把 `if (loading) return <Spinner />` 写在了 `useState` / `useEffect` 之间——条件命中时后面的 hook 根本没执行，未命中时又执行了，hook 顺序不稳定。

处理：所有 hook 与函数定义写在前面，`return` 统一放到它们之后。这类错误不会在类型检查里暴露，只能靠运行发现。

## 3. 依赖只在 uv 环境里存在

现象：用系统 Python 跑任何后端脚本都报 `ModuleNotFoundError: pydantic`。

原因：项目依赖装在 uv 管理的环境里，系统 Python 是干净的。

正确调用：`uv run --project backend --locked python ...`；并且要先恢复 PATH 才能找到 `uv` 和 `git`（本机 PATH 在某些会话里不完整）。

## 4. 本地无法验证飞书免登：内网穿透走不通

试过两条路都失败：

- `localtunnel`：给的是带安全确认页的中转地址，飞书客户端打不开；
- `ngrok`：被本机杀毒软件拦截。

结论：没有公网域名就无法完成 `requestAuthCode → 后端换 open_id` 的真实链路测试。所以本地只做身份依赖桩，接口形状按正式实现预留，明确标注"部署后联调"，不假装本地已验证。

## 5. 私聊消息不会自动进业务模块

平台层的路由规则决定消息归属：普通私聊默认进对话/助手，只有带明确指令前缀的消息才进志愿、报销等业务模块。

这意味着两件事：

1. 网页入口按钮必须带清晰指令，否则用户点进来只会得到闲聊回复；
2. 任何"让某类普通对话也走业务模块"的改动，都必须改平台层路由，不能在业务模块里堆判断——那样会影响其他模块的分流。

（曾尝试给私聊加一条"含特定人名就回固定话术"的路由，评估后放弃并回退：它改的是公共路由，收益低、风险高。）

## 6. 代码归属靠 git，不靠标记

验证过的事实：同一个文件里往往混着多人代码（例如前端页面 708 行中 429 行是我写的，后端业务文件 600 行里我只占 11 行）。

所以：

- 归属证据是提交作者、PR 记录、`git blame`，不是注释里的名字，更不是暗记或水印；
- 在别人的文件里"挂名"既不成立也不体面；
- 公开作品集只能放自己 100% 编写的文件，混编文件整体搬过去等于冒认队友的工作。

## 7. 别被"整体测试失败"吓到，先看失败归属

项目检查里集成测试出现 48 个失败，逐条核对后全部集中在知识库、群助手、报销、编码类历史用例（utf-8/gbk 解码、旧断言与新逻辑不符），与志愿模块无关。

正确做法：先按模块归类失败项，确认是否落在本次改动范围，再决定是否需要修；不能因为"有失败"就笼统说"全绿"，也不能把无关失败算到自己头上。
