# 简历版项目经历

## 项目条目（可直接用）

**宣怀社团飞书智能服务台｜飞书生态全栈开发｜2026.10–2026.11**

在社团飞书自建应用（FastAPI + SQLite + React/Vite）中，负责报销与志愿两个网页入口的接入与前端实现，与机器人端共用身份、数据与校验规则。

- **报销网页飞书集成**：独立实现飞书一键登录与 OAuth 回调、登录页自动登录，打通"飞书身份 → 内部成员"映射；新增服务间 token 鉴权、发票撤销与补件重提接口，修复电子发票 OCR 字段缺失，支撑主项目以服务方式提交与联调。
- **志愿时长网页应用**：基于既有原型改造为六页 H5（活动列表、志愿登记、我的记录、我的时长、导出、管理），实现普通成员/管理员双视图；移除全部手填身份输入，身份统一取自飞书登录态；补充提交二次确认、时长按活动筛选、负责人补录与全量导出。
- **双入口一致性**：网页与机器人共用同一后端 service 层与同一数据库作用域，防重复、状态机、时长取整规则只维护一份；后端按依赖注入预留身份校验替换点，正式环境直接换 OAuth 实现。
- **入口与部署**：机器人帮助卡片新增"打开网页版"按钮（由环境变量控制，未配置不显示）；引入飞书 JSAPI SDK；输出部署说明，覆盖环境变量、H5 可信域名、OAuth 回调与验收清单。
- **边界验证**：本地逐项实测重叠时段拦截、非法时间参数、驳回必填意见、重复审核、取消不写入、断网明确报错等场景，并跑通项目 lint 与格式检查。

## 面试问答准备（照实回答，不夸大）

**Q：数据一致性怎么保证？两个入口会不会各查一套？**
A：网页不新建数据库，直接复用机器人模块的 service 层和同一业务作用域（应用 + 租户 + 运行模式派生）。如果网页另起作用域，就会出现"机器人有记录、网页空数据"，这是设计时明确规避的点。

**Q：怎么防重复登记和重复审核？**
A：防重复在 service 层，不靠前端按钮禁用：同一成员时段重叠直接拒绝（返回 `overlapping_record`），状态机保证已通过的记录不能再被二次审核；并发上模块有作用域级锁。

**Q：权限是前端藏按钮还是后端拦？**
A：两边都做，但以后端为准。现在后端身份依赖还是桩函数（本地固定测试用户），正式环境替换成 OAuth 后，审核人/负责人/导出人名单校验落在后端；这一项我在验收清单里明确标了"未实现"。

**Q：你在这个项目里做了多少？**
A：报销我负责的是集成层（登录、鉴权、撤销/补件、OCR 修复），核心业务是队友早期导入的既有系统；志愿我负责网页前端、机器人入口和身份框架，后端的模型、状态机与时长计算是队友实现的。按功能口径说，不说全项目百分比。

**Q：本地怎么验证飞书免登？**
A：验证不了真实的。localtunnel 有安全确认页、ngrok 被杀毒软件拦，没有公网域名就拿不到真实授权码，所以本地是身份桩 + 接口形状预留，明确标注"部署后联调"，没有假装测过。
